# 功能优先级清单

更新时间：2026-04-28

## 1. 使用说明

这份清单只关注当前阶段真正要做的功能，不展开商城、地图、医院、社交、硬件等扩展方向。

目标只有一个：先把宠物养成小程序的基础记录能力做完整、做稳定、做顺畅。

## 2. 当前阶段原则

当前阶段优先级判断：

- 先做基础功能闭环
- 再做统计和联动增强
- 最后再考虑智能化和商业化

当前阶段暂不进入：

- 商城
- 地图
- 医院/周边服务
- 社交动态
- 硬件联动

## 3. P0 核心必做

这些功能属于当前版本必须优先完成的内容。

### 3.1 登录与用户状态

目标：

- 用户可以正常登录
- 页面能识别登录态
- 未登录时有明确兜底

前端：

- 统一登录态读取和失效处理
- 所有需要登录的页面补齐未登录空态

后端：

- 统一认证校验入口
- 保证所有用户数据按用户隔离

当前状态：

- 已有登录页面
- 已有认证接口
- 仍需继续统一页面登录态判断

### 3.2 宠物档案

目标：

- 可以新增、编辑、查看、删除宠物
- 支持宠物切换
- 宠物是所有记录模块的主维度

前端：

- `PetProfile`
- `EditPetProfile`
- `PetDetailPage`

后端：

- 宠物 CRUD
- 宠物详情
- 宠物概览

当前状态：

- 基本已具备
- 仍需继续核对字段完整性和页面细节

### 3.3 日程提醒

目标：

- 可以新增提醒
- 可以查看提醒列表和日历
- 可以更新状态
- 可以按宠物查看

前端：

- `PetSchedule`
- `AddPetReminder`
- `SendPetSchedule`

后端：

- 提醒 CRUD
- 状态过滤
- 宠物维度过滤

当前状态：

- 主流程已经有了
- 还需要继续核对提醒分类、状态和交互完整性

### 3.4 基础记录

目标：

- 花销记录可用
- 护理记录可用
- 日常记录可用
- 所有记录都能关联宠物

前端：

- `AddPetRecord`
- `PetExpenseStats`
- `PetCareStats`
- `PetSchedule` 中的记录聚合

后端：

- 花销、护理、日常记录 CRUD
- 按宠物过滤
- 时间排序

当前状态：

- 基础接口和页面已接入
- 统计页和记录页完成度仍不一致

### 3.5 食物 / 用药 / 里程碑

目标：

- 三个模块都先完成基础增删改查
- 页面可以正常展示列表和基础字段

前端：

- `PetFood`
- `PetMedicine`
- `PetMilestones`

后端：

- 三个模块的 CRUD
- 按宠物过滤

当前状态：

- 页面和接口都已存在
- 还需要统一空态、表单、列表信息密度

### 3.6 知识库

目标：

- 分类浏览
- 文章列表
- 文章详情
- 搜索

前端：

- `PetKnowledge`
- `PetArticleDetail`

后端：

- 分类接口
- 文章列表接口
- 文章详情接口

当前状态：

- 主链路已经可用
- 属于当前项目里相对完整的模块之一

## 4. P1 重要增强

这些功能不是第一优先，但在 P0 稳定后应尽快补齐。

### 4.1 聚合页准确性

目标：

- 我的页、档案页、报告页、服务页的数据准确
- 聚合字段定义稳定

前端：

- `PetOwner`
- `PetProfile`
- `PetReport`
- `PetServiceCenter`

后端：

- Dashboard 聚合查询优化
- 避免全表查询
- 避免跨用户数据混入

当前状态：

- 已有接口
- 是当前最值得继续收口的一块

### 4.2 时间线与报告

目标：

- 时间线按时间排序稳定
- 报告页指标可解释
- 最近事件和统计口径统一

前端：

- `PetTimeline`
- `PetReport`

后端：

- 时间线聚合
- 报告统计

当前状态：

- 页面和接口存在
- 更偏“可展示”，还需要继续变成“可依赖”

### 4.3 反馈与用户页闭环

目标：

- 用户可以提交反馈
- 我的页可以形成“个人中心”闭环

前端：

- `PetOwner`
- `PetFeedback`

后端：

- 反馈 DTO 校验
- 反馈列表、创建、删除

当前状态：

- 已有基础能力
- 适合作为 P1 收尾项

## 5. P2 稳定性与体验收口

这些内容不一定是新功能，但会直接影响项目是否真正可用。

### 5.1 前端

- 修复中文乱码
- 统一主链路页面体验
- 补齐空态、异常态、无宠物态
- 统一数据来源和刷新方式

### 5.2 后端

- 统一认证方式
- 统一 DTO 校验
- 统一返回结构
- 统一时间字段格式
- 优化重复 Service 逻辑

## 6. 当前不进入排期的内容

以下内容先明确不排入当前核心开发：

- 商城
- 地图
- 医院/周边服务
- 社交功能
- 硬件联动
- 复杂会员体系
- 高成本 AI 个性化系统

这些方向可以保留在长期规划里，但不进入当前冲刺周期。

## 7. 推荐开发顺序

### 第一轮

先完成以下事项：

1. 登录态和用户隔离收口
2. 宠物档案、提醒、基础记录链路核对
3. 食物、用药、里程碑三个模块补齐可用性
4. 知识库和反馈页收尾

### 第二轮

再做以下事项：

1. 我的页聚合数据
2. 档案页聚合数据
3. 时间线
4. 报告页
5. 服务页

### 第三轮

最后再统一质量：

1. 前端状态管理和接口接入方式
2. 后端认证、校验、聚合查询
3. 页面空态、异常态和交互体验

## 8. 一句话结论

当前项目的正确节奏不是继续扩功能范围，而是围绕“宠物档案、提醒、记录、统计、知识库”这条主线，把已有能力逐步做稳。
